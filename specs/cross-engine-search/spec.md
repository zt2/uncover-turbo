# Spec · 自然语言跨多测绘引擎查询与聚合去重

> SDD 阶段一产出物。本文件只定义「做什么、为什么、验收标准」,不涉及实现细节(实现细节属于 `plan.md`)。
> **状态:已确认(§5 决策已拍板)。** 可进入阶段二（Plan）。

## 1. 需求背景 / 目标

当前 `uncover-turbo` 的局限:
- 一次运行只面向**单个**引擎(main.go 逐个引擎翻译后交给 uncover 的 `runner` 执行);
- LLM 后端**硬编码**为 OpenAI + GPT-3.5(`sashabaranov/go-openai`,固定模型);
- 输出直接复用 uncover `runner` 的格式化逻辑,字段是各引擎归一化后的**公共小集**(IP / Port / Host / Url);
- 无跨引擎聚合去重,无结构化 JSON/彩色输出的统一控制,核心逻辑与 CLI 耦合。

目标:把它重构为一个「自然语言 → 多测绘引擎并发查询 → 聚合去重 → 富字段统一输出」的工具,并让**核心能力与展示层解耦**,为未来 Web 形态留出扩展空间。

具体能力:
1. **三层查询链路(核心架构)**:
   - **上层** 自然语言 → **通用中间层 IR**(引擎无关的机器查询语法,可序列化);这是**唯一**用到 LLM 的一步。
   - **中层** IR 本身是稳定、可被机器直接构造/调用的表示 → 非人程序可**绕过自然语言与 LLM**,直接提供 IR。
   - **下层** IR → **各测绘引擎专有查询语法**,为**确定性编译**(纯代码,不经 LLM)。
   用户输入一条自然语言,经上层→中层→下层后,**并发**查询所有启用引擎。
2. 支持的引擎至少覆盖 censys、hunter、fofa、zoomeye,并可平滑扩展到 uncover 支持的其它引擎(shodan、quake、netlas、criminalip 等)。
3. **LLM 后端可配置**:支持 OpenAI、OpenRouter 及任意 OpenAI 兼容后端(可配 base URL / 模型 / API Key),无需改代码即可切换。
4. **引擎可启用/禁用**:通过配置文件和/或命令行控制;禁用的引擎绝不发起请求。
5. **聚合去重**:把不同引擎返回、指向同一资产的结果合并为**一条**记录。
6. **富字段合并**:合并后的记录按「最丰富标准」取各引擎字段的**并集(超集)**,而非公共交集;并保留每条记录由哪些引擎贡献(provenance)。
7. **CLI 形态**,同时支持:
   - 人类可读的标准输出,带**颜色**(非 TTY 或显式关闭时自动禁用颜色);
   - `--json` 结构化输出。
8. **架构可演进为 Web**:核心逻辑(翻译 / 查询 / 聚合)不做任何直接的 stdout / `os.Exit`,以纯数据结构返回,CLI 只是其中一个前端。

## 2. 验收标准(可验证)

> 下列每条均应可通过运行或测试验证。凡涉及真实引擎/LLM 的联网项,以「可观察行为 + 可注入的假后端单测」双重验收。

- **AC1 · 多引擎并发翻译与查询**:启用 ≥2 个引擎并提供有效凭据时,单条自然语言查询先被翻译为通用 IR,再由 IR 确定性编译出每个启用引擎各自的查询语法(verbose 下可见),并并发查询所有启用引擎。
- **AC9 · 中间层可独立调用(机器友好)**:
  - 通用 IR 有稳定、可序列化的表示(如 JSON),机器调用方可**直接提供 IR**(绕过自然语言 / LLM),得到同样的跨引擎聚合结果;
  - **IR → 各引擎语法为确定性转换**,同一 IR 对同一引擎恒定产出同一查询串,不经 LLM;
  - 某引擎无法表达 IR 中的某谓词时,行为明确(该引擎降级/报错并记录,不静默产出错误查询)。
- **AC2 · 聚合去重**:多个引擎返回的、判定为「同一资产」的结果合并为一条输出;不同资产保持独立。判定规则见 §5 开放决策(确认后写死为验收口径)。
- **AC3 · 富字段并集**:合并记录包含所有贡献引擎可提供字段的**并集**;某字段只要有任一引擎提供了值就保留(非空优先),不因其它引擎缺该字段而丢弃。每条记录带 `sources` 列出全部贡献引擎。
- **AC4 · 输出双形态**:
  - `--json` 输出结构化 JSON,每条资产一个对象,含 `sources` 与合并后的全部字段;
  - 默认(非 JSON)输出人类可读行,带颜色;`--no-color` 或非 TTY 时无 ANSI 颜色码。
- **AC5 · 引擎启用/禁用**:可经配置文件与命令行开关控制引擎启停;被禁用的引擎不产生任何网络请求(可由假后端/日志验证)。
- **AC6 · LLM 后端可配置**:通过配置/环境变量即可将后端指向 OpenAI 或 OpenRouter(或任意 OpenAI 兼容端点),切换 base URL / 模型 / Key 均无需改动代码。
- **AC7 · 核心与展示解耦**:核心包对外暴露「输入自然语言 + 配置 → 返回聚合结果数据结构」的接口,内部不写 stdout、不调 `os.Exit`;CLI 与(未来)Web 均可复用同一核心。
- **AC8 · 质量门禁**:`go build ./...`、`go vet ./...`、`go test ./...` 全部通过;核心聚合/去重/富字段合并逻辑有单元测试覆盖(可用 mock 引擎结果,不依赖真实网络)。

## 3. 影响面

- **允许完全重构**(用户已明确授权)。预期改动:
  - 用 OpenAI 兼容的**通用 LLM 客户端**替换硬编码 OpenAI 调用;
  - **绕开 uncover 的 `runner`**(它占用了输出格式化),改用更底层的 `uncover.Service.Execute(ctx)`(返回 `sources.Result` 流,含原始 `Raw` 字节)来拿到结果与各引擎原始 JSON,从而支持富字段;
  - 新增**配置文件**(引擎开关、凭据、LLM 后端);
  - 新增核心包(翻译、查询编排、聚合去重、字段合并)与独立的输出/渲染层。
- **依赖**:优先复用 uncover v1.2.1 SDK(已内置 censys/hunter/fofa/zoomeye 等 19 个引擎的鉴权与分页);仅当某引擎无法通过 uncover 拿到所需富字段时,才自行实现该引擎客户端(用户已授权「不满足就自己实现」)。
- **安全**:凭据仅经环境变量/配置文件注入,不硬编码、不写入日志;本工具用于授权范围内的资产测绘。
- **兼容性**:CLI 参数与旧版不保证兼容(重构);README 需相应更新(纳入 Tasks 阶段)。

## 4. 非目标(本次不做)

- 不实现 Web 前端本身,仅保证架构可扩展。
- 不新增 uncover 尚不支持、且本次需求未要求的引擎。
- 不做结果持久化 / 数据库 / 历史检索。
- 不做 LLM 之外的查询语法「规则式」翻译引擎(仍以 LLM 翻译为主)。
- 不做分布式/任务队列/并发限流之外的调度编排。

## 5. 已确认决策(验收口径)

1. **资产去重身份(影响 AC2/AC3)**:以 **`IP:Port` 为主键**。同一 `IP:Port` 判定为同一资产;`host` 作为**可多值属性**并入该记录的 `hosts` 集合(同一 IP:Port 上的多个域名合并到一条记录)。IP 为空时的退化处理在 Plan 中细化(如以 `host:port` 兜底)。
2. **配置文件**:**YAML**,默认位置 `~/.config/uncover-turbo/config.yaml`;敏感凭据允许**环境变量覆盖**。
3. **LLM 客户端**:沿用 **`sashabaranov/go-openai`**,通过**自定义 `BaseURL`** 适配 OpenAI / OpenRouter / 任意 OpenAI 兼容端点。
4. **文档语言**:spec / plan / tasks 及 README **统一中文**。
